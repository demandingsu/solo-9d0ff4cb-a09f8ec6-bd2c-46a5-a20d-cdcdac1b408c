# 隔声试验数据交付复核工具

声学实验室向外部复核方交付隔声试验数据的网页工具，包含两个功能：

1. **单室子库导出**：从上传的 SQLite 库中勾选试验、剔除个别异常读数，
   沿对照/校准引用自动补齐所需记录，确认预览后下载 SQLite 子库；
2. **双分室合库**（首页“双分室合库工作台”入口）：复核员在一个合库中查看
   甲、乙两个分室的隔声试验，支持首次双库上传、单独换库、编号对照查看与
   合库下载，报告引用的合库编号可在库内对照中核对。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000，点击“双分室合库工作台”
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements-dev.txt
python3 scripts/make_sample_db.py sample.db          # 单室演示库
python3 scripts/make_branch_dbs.py branch_dbs        # 甲、乙分室示例子库（同号）
uvicorn app.main:app --reload
```

运行测试：`pytest`

## 数据库结构约定

上传的 SQLite 库需包含四张表（关键列名固定，其余列任意）：

| 表 | 关键列 | 说明 |
| --- | --- | --- |
| `groups` | `id`, `name` | 试验组 |
| `calibrations` | `id`, `device` | 校准记录 |
| `tests` | `id`, `group_id→groups`, `calibration_id→calibrations`(可空), `name` | 试验 |
| `readings` | `id`, `test_id→tests`, `calibration_id→calibrations`(可空), `control_reading_id→readings`(可空), `kind` | 读数；`control_reading_id` 为对照读数引用，允许跨组 |

## 交付规则

1. 交付所选试验中未被剔除的全部读数；
2. 沿对照引用（`control_reading_id`）与校准引用（`calibration_id`，读数级与试验级）
   补齐所需记录；对照读数允许跨组互引；
3. 跨到未勾选的组时，只带入沿引用找到的读数，以及这些读数所属的试验、
   试验所属的组（维持外键完整所必需）和引用到的校准记录；
4. 引用悬空（目标不存在）或指向已剔除读数时，预览页展示完整引用链并**阻止下载**；
5. 子库建表语句复用源库 DDL 原文，主键、外键约束、索引原样保留，行按原主键写入，
   导出后执行 `PRAGMA foreign_key_check` 校验。

## 使用流程

1. **上传**：选择实验室导出的 SQLite 库（结构不符会给出具体缺失项）；
2. **选择**：按组勾选要交付的试验，可在所选试验下勾选要剔除的异常读数；
3. **预览**：查看交付汇总、跨组带入的读数及其引用链；若存在引用冲突，
   展示每条冲突的完整引用链，下载按钮禁用；
4. **下载**：确认后下载 `*_subset.db`。下载前服务端会重新解析一次，
   若状态已变化产生冲突则返回 409 拒绝。

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATA_DIR` | `./data`（容器内 `/data`） | 上传文件与子库的工作目录 |
| `MAX_UPLOAD_MB` | `200` | 上传大小上限 |

## 双分室合库规则

入口：首页 → 双分室合库工作台（`/merge`）。两份分室子库都采用上面的项目示例
表结构（四表、关键列名固定）。

1. **首次合库**：必须同时上传甲、乙两份子库；之后每个分室可单独上传新版
   替换（即“换库”）；
2. **编号体系**：合库四表（groups / calibrations / tests / readings）保留
   全部在库记录，每行赋予合库编号；分室原编号不变，仅外键被重写为合库编号；
3. **引用归属**：分组归属、试验归属、对照读数（`control_reading_id`）、
   校准引用（读数级与试验级 `calibration_id`）一律只在各自分室内解析，
   分室之间不串扰；
4. **编号对照**：合库内附 `merge_id_map` 表，逐行记录
   `branch（分室）、table_name（表）、original_id（原编号）、merged_id（合库编号）、
   status（present 在库 / withdrawn 已撤下）`；网页“查看编号对照”可按分室、表筛选，
   报告引用的合库编号可在此核对；另有 `merge_branches` 记录各分室来源文件与更新时间；
5. **撤下与补回**：新版分室库中消失的记录从合库数据表移除，对照保留为
   withdrawn；日后补回时沿用原合库编号；该合库编号永久占用，绝不转给其他记录；
6. **悬空拒收**：新版分室库若存在悬空外键（目标记录不存在），网页列出涉及的
   表、行、列与相关编号并整份拒收，不合库；结构不符或列结构与现合库不一致同样拒收；
7. **失败保护**：换库先写临时文件并完整校验，再原子替换；失败时旧合库、
   分室文件与编号对照原样保留，当前合库仍可下载；
8. **持久化**：分室文件与合库全部落在 `DATA_DIR/merge`（Docker 卷 `labdata`），
   不依赖进程内存，重启后仍可下载与换库；
9. **两边都换**：两个分室先后各自换库，成功的更新都会纳入合库。

## 已知限制

- 会话保存在单进程内存中，重启后需重新上传；上传文件保留在 `DATA_DIR`，
  需运维定期清理（未实现自动清理）；
- 未做多用户隔离与鉴权，仅供实验室内网使用；
- 表名/关键列名固定，如实验室库结构不同需先适配（见 `app/core.py` 顶部约定）。
